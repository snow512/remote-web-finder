# 워크스페이스 관리 규칙

이 폴더는 프로젝트의 워크스페이스(멀티 클론)를 관리합니다.
동일한 저장소를 여러 디렉토리에 독립적으로 클론하여 병렬 작업할 때
각 워크스페이스의 진행 현황, 환경 설정, 브랜치 상태를 추적합니다.

---

## 폴더 구조

```
.madang/categories/workspaces/workspaces.md          ← 이 파일 (규칙)
.madang/categories/workspaces/workspace-guide.md     ← 워크스페이스 운영 가이드

docs/workspaces/
├── workspace-{name}.md                  ← 개별 워크스페이스 진행 현황
└── .archive/                            ← 아카이브된 진행 기록
    └── {YYYY-MM}/
        └── workspace-{name}-{date}.md
```

---

## 워크스페이스란?

동일한 저장소를 여러 디렉토리에 **개별 클론**하여 독립적으로 작업하는 환경입니다.
git worktree와 달리 각 클론은 완전히 독립된 `.git` 디렉토리를 가지며,
`git push/pull`로 변경사항을 동기화합니다.

```
~/Workspace/
├── my-project/           ← 메인 워크스페이스 (첫 번째 클론)
├── my-project-second/    ← 두 번째 워크스페이스 (별도 클론)
└── my-project-third/     ← 세 번째 워크스페이스 (별도 클론)
```

각 클론은 서로 다른 브랜치에서 독립적으로 작업하고,
원격 저장소를 통해 코드와 진행 현황을 공유합니다.

---

## 관리 규칙

1. **워크스페이스 등록:** `workspace-{name}.md` 파일 생성 (예: `workspace-main.md`, `workspace-second.md`)
2. **자기 파일만 수정** — 각 워크스페이스는 자신의 진행 파일만 수정한다
3. **다른 워크스페이스 파일은 읽기 전용** — 참고만 하고 수정하지 않는다
4. **git push/pull로 공유** — 진행 파일을 커밋·푸시하여 다른 워크스페이스에서 pull로 수신
5. **상태 변경 시 즉시 업데이트** — 작업 시작/완료, 브랜치 전환/머지 시 먼저 업데이트
6. **오래된 기록 아카이브** — `.archive/{YYYY-MM}/`에 `workspace-{name}-{date}.md`로 보관
7. **파일명 형식:** `workspace-{name}.md` — name은 소문자 영문 (main, second, third 등)
8. **모든 워크스페이스 파일은 YAML frontmatter 헤더가 필수** (아래 템플릿 참조)

## 포트 체계

워크스페이스별 포트 충돌을 방지하기 위해 체계적으로 할당합니다.

| 워크스페이스 | FE | BE | DB |
|-------------|------|------|------|
| main | x000 | x001 | x002 |
| second | x100 | x101 | x102 |
| third | x200 | x201 | x202 |

- `x`는 프로젝트별 기본 번호 (예: 5 → 5000/5001/5002)
- 각 워크스페이스는 100 단위로 분리
- `.env.local`로 포트 오버라이드 (`.env`는 기본값 유지)

---

## 환경 변수 관리

### 원칙
- `.env` — 기본값(main 워크스페이스), git 추적
- `.env.local` — 비밀정보 + 워크스페이스별 포트 오버라이드, git 미추적
- `.env.local`이 `.env`보다 우선 적용

### 워크스페이스별 .env.local 설정
- **main**: 오버라이드 불필요 (`.env` 기본값 사용)
- **second**: 포트를 x1xx 대역으로 오버라이드
- **third**: 포트를 x2xx 대역으로 오버라이드
